\section*{Project Overview}

RaceShowdown compares two athletes in a toy race-eating scenario:
\begin{itemize}
    \item both athletes first eat the same number of hot dogs,
    \item both athletes then run the same distance,
    \item the faster total time wins.
\end{itemize}

The codebase evaluates this matchup in two ways:
\begin{itemize}
    \item a \textbf{deterministic model}, which compares mean total times,
    \item a \textbf{probabilistic model}, which adds noise and estimates win probabilities by Monte Carlo simulation.
\end{itemize}

The main entry point loads the TOML configuration, builds a distance-hot-dog grid, and produces:
\begin{itemize}
    \item a probabilistic phase diagram, showing $P(\text{athlete A wins})$,
    \item a deterministic phase diagram, showing which athlete has the lower mean time,
    \item printed reference probabilities at a few named scenarios from the config file.
\end{itemize}

\section*{Current Mathematical Model}

\subsection*{Inputs}

For a race we specify:
\begin{itemize}
    \item $n \geq 0$: number of hot dogs eaten,
    \item $d > 0$: running distance in meters.
\end{itemize}

All distances are in meters and all times are in seconds.

\subsection*{Eating Time}

For athlete $i$, the time to eat the $m$-th hot dog is modeled as
\[
e_i(m) = a_i + b_i m,
\]
where:
\begin{itemize}
    \item $a_i$ is the base eating time,
    \item $b_i$ is the per-hot-dog slowdown.
\end{itemize}

The cumulative mean time to eat $n$ hot dogs is
\[
E_i(n) = \sum_{m=1}^{n} (a_i + b_i m).
\]

\subsection*{Post-Eating Running Penalty}

After eating $n$ hot dogs, the running component is multiplied by
\[
M_i(n) = 1 + c_i n + q_i n^2,
\]
where:
\begin{itemize}
    \item $c_i$ is a linear post-eating penalty,
    \item $q_i$ is a quadratic post-eating penalty.
\end{itemize}

This is a simple way to capture the idea that running becomes harder after heavier eating.

\subsection*{Running Time: Two-Regime Model}

The current project does \emph{not} use a single running curve for all distances.
Instead, it uses a sprint regime up to a threshold distance $d_s$ and an endurance regime beyond that threshold.

\paragraph{Why the old single-curve idea was not enough.}
A single Riegel-style power law can fit middle and long distances reasonably well, but it is too rigid for sprint specialists. If one exponent must explain both 100m and 5000m, then an athlete who is exceptional at short sprints tends to become unrealistically dominant at longer distances too. The current model separates these effects.

\paragraph{Endurance regime.}
For $d > d_s$, athlete $i$ uses a Riegel-style law
\[
R_i^{\text{long}}(d) = T_{i,\mathrm{ref}} \left(\frac{d}{d_{\mathrm{ref}}}\right)^{k_i},
\]
where:
\begin{itemize}
    \item $T_{i,\mathrm{ref}}$ is the runner's time at the endurance reference distance,
    \item $d_{\mathrm{ref}}$ is the endurance reference distance,
    \item $k_i$ is the endurance exponent.
\end{itemize}

Interpretation:
\begin{itemize}
    \item lower $T_{i,\mathrm{ref}}$ means a faster runner around the reference distance,
    \item lower $k_i$ means better endurance,
    \item larger $k_i$ means the runner slows down faster as distance increases.
\end{itemize}

\paragraph{Sprint regime.}
For $d \leq d_s$, athlete $i$ uses a sprint-oriented power law
\[
R_i^{\text{short}}(d) = T_{i,\mathrm{sprint}} \left(\frac{d}{d_{\mathrm{sprint}}}\right)^{\alpha_i},
\]
where:
\begin{itemize}
    \item $T_{i,\mathrm{sprint}}$ is the athlete's sprint reference time,
    \item $d_{\mathrm{sprint}}$ is the sprint reference distance,
    \item $\alpha_i$ is chosen so that the short and long regimes match exactly at $d_s$.
\end{itemize}

The continuity condition is
\[
R_i^{\text{short}}(d_s) = R_i^{\text{long}}(d_s),
\]
which gives
\[
\alpha_i
=
\frac{
\log\!\left(R_i^{\text{long}}(d_s) / T_{i,\mathrm{sprint}}\right)
}{
\log\!\left(d_s / d_{\mathrm{sprint}}\right)
}.
\]

This means:
\begin{itemize}
    \item \textbf{sprint ability} is primarily controlled by $T_{i,\mathrm{sprint}}$,
    \item \textbf{endurance ability} is primarily controlled by $T_{i,\mathrm{ref}}$ and $k_i$,
    \item the transition at $d_s$ is continuous by construction.
\end{itemize}

\paragraph{Full running model.}
The mean running time used by the simulator is
\[
R_i(d,n) =
\begin{cases}
R_i^{\text{short}}(d) \, M_i(n), & d \leq d_s, \\
R_i^{\text{long}}(d) \, M_i(n), & d > d_s.
\end{cases}
\]

\subsection*{Total Mean Race Time}

The full deterministic race time is
\[
T_i(d,n) = E_i(n) + R_i(d,n).
\]

The deterministic comparison between athletes $A$ and $B$ is
\[
\Delta(d,n) = T_A(d,n) - T_B(d,n).
\]

Interpretation:
\begin{itemize}
    \item $\Delta(d,n) < 0$: athlete $A$ is faster on mean time,
    \item $\Delta(d,n) > 0$: athlete $B$ is faster on mean time,
    \item $\Delta(d,n) = 0$: deterministic tie.
\end{itemize}

\subsection*{Probabilistic Model}

The Monte Carlo layer samples noise around the mean model:
\begin{itemize}
    \item additive eating noise,
    \item multiplicative sprint-reference-time noise,
    \item multiplicative endurance-reference-time noise,
    \item multiplicative endurance-exponent noise,
    \item multiplicative post-eating-penalty noise.
\end{itemize}

This produces random total race times $\widetilde{T}_A(d,n)$ and $\widetilde{T}_B(d,n)$.
The estimated win probability is
\[
p(d,n) = \Pr\!\bigl(\widetilde{T}_A(d,n) < \widetilde{T}_B(d,n)\bigr).
\]

\section*{Configuration Guide}

The configuration file is \texttt{config/config.toml}. It has three main sections:
\begin{itemize}
    \item \texttt{[simulation]}
    \item \texttt{[running\_model]}
    \item \texttt{[running\_model.runners.<name>]}
\end{itemize}

\subsection*{Simulation Attributes}

\begin{description}
    \item[\texttt{athlete\_a}, \texttt{athlete\_b}] The two named athletes compared in the plots and reference outputs.
    \item[\texttt{min\_distance\_m}, \texttt{max\_distance\_m}] The distance range used for the phase diagrams.
    \item[\texttt{distance\_samples}] Number of distance grid points between the minimum and maximum.
    \item[\texttt{max\_hotdogs}] Largest hot-dog count shown on the grid.
    \item[\texttt{monte\_carlo\_samples}] Number of Monte Carlo samples per grid cell for the probabilistic plot.
    \item[\texttt{random\_seed}] Seed used for reproducible simulations.
    \item[\texttt{[[simulation.reference\_checks]]}] A small list of named scenarios printed after the plots as quick sanity checks.
\end{description}

\paragraph{Current choices.}
The project currently studies distances from 100m to 5000m, uses 120 distance samples, and considers 0 to 20 hot dogs. This range matches the intended scope of the running model: short sprint through 5k, not 10k or marathon modeling.

\subsection*{Global Running-Model Attributes}

\begin{description}
    \item[\texttt{sprint\_threshold\_distance}] The regime switch distance $d_s$.
    \item[\texttt{sprint\_reference\_distance}] The short-distance anchor $d_{\mathrm{sprint}}$ used with \texttt{sprint\_ref\_time}.
    \item[\texttt{reference\_distance}] The endurance reference distance $d_{\mathrm{ref}}$ used with \texttt{ref\_time}.
    \item[\texttt{max\_modeled\_distance}] Hard upper bound for the supported running model.
\end{description}

\paragraph{Current choices.}
\begin{itemize}
    \item \texttt{sprint\_threshold\_distance = 400.0}: 400m is a natural cutoff between pure sprint behavior and distances where endurance matters more.
    \item \texttt{sprint\_reference\_distance = 100.0}: 100m is the cleanest sprint reference because it directly represents raw short-distance speed.
    \item \texttt{reference\_distance = 1500.0}: 1500m is a good middle anchor for a model intended to cover roughly 400m--5000m.
    \item \texttt{max\_modeled\_distance = 5000.0}: the current toy model is intentionally limited to this range.
\end{itemize}

\subsection*{Runner-Type Endurance Categories}

The table \texttt{[running\_model.runner\_types]} defines reusable endurance exponents.
These categories describe endurance quality only. They do \emph{not} describe sprint speed.

\begin{center}
\begin{tabular}{|l|c|p{8cm}|}
\hline
\textbf{Category} & \textbf{$k$} & \textbf{Interpretation} \\
\hline
\texttt{elite} & 1.05 & Strong endurance. Performance degrades relatively slowly with distance. \\
\hline
\texttt{high} & 1.06 & Better than average endurance. Close to the classic Riegel ballpark for trained runners. \\
\hline
\texttt{average} & 1.07 & Middle-of-the-road endurance for this toy model. \\
\hline
\texttt{low} & 1.09 & Noticeably weak endurance. Times grow faster with distance. \\
\hline
\texttt{bad} & 1.11 & Poor endurance. Useful for athletes whose short-distance strength should fade rapidly as distance grows. \\
\hline
\end{tabular}
\end{center}

\paragraph{Why these values were chosen.}
The Riegel exponent is often near 1.06 for reasonably trained distance performance, so the current categories are centered near that value. The range 1.05 to 1.11 is broad enough to create visible separation between endurance profiles without making the toy model numerically unstable.

\subsection*{Per-Runner Attributes}

Each runner entry combines the running model with the eating model.

\begin{description}
    \item[\texttt{sprint\_ref\_time}] Sprint reference time at \texttt{sprint\_reference\_distance}. Lower means faster sprint ability.
    \item[\texttt{ref\_time}] Endurance reference time at \texttt{reference\_distance}. Lower means faster around 1500m.
    \item[\texttt{type}] Which endurance category to use from \texttt{runner\_types}.
    \item[\texttt{eat\_base\_sec}] Base seconds for eating each hot dog.
    \item[\texttt{eat\_slowdown\_sec}] Extra eating delay added per hot dog eaten.
    \item[\texttt{post\_eat\_linear}] Linear increase in the running penalty after eating.
    \item[\texttt{post\_eat\_quadratic}] Quadratic increase in the running penalty after eating.
    \item[\texttt{eat\_noise\_sec}] Standard deviation of per-hot-dog eating noise.
    \item[\texttt{run\_sprint\_ref\_time\_rel\_std}] Relative noise scale on sprint reference time.
    \item[\texttt{run\_ref\_time\_rel\_std}] Relative noise scale on endurance reference time.
    \item[\texttt{run\_endurance\_rel\_std}] Relative noise scale on the endurance exponent.
    \item[\texttt{post\_eat\_rel\_std}] Relative noise scale on the post-eating running multiplier.
\end{description}

\section*{How to Read the Outputs}

\begin{itemize}
    \item The \textbf{probability plot} shows where athlete A wins often, rarely, or about half the time.
    \item The \textbf{deterministic plot} shows where the mean model favors one athlete over the other.
    \item The \textbf{tie curve} on the deterministic plot marks where the mean total times are equal.
    \item The printed \textbf{reference probabilities} are just spot checks from the config file.
\end{itemize}

The plot matches the intended story of the model. For short distances with enough hot dogs, Chestnut's eating advantage can outweigh Bolt's running advantage, so the lower part of the chart becomes bright. For longer distances, Bolt's stronger running parameters dominate, so the upper region stays dark unless the eating burden becomes very large. The boundary curve therefore slopes upward: as distance increases, Chestnut needs Bolt to be penalized by more hot dogs before the matchup becomes competitive.

\section*{Summary}

The current project is a configurable toy simulator for ``eat first, then run'' matchups.
Its main modeling choices are:
\begin{itemize}
    \item a linear-plus-slowdown eating model,
    \item a multiplicative post-eating running penalty,
    \item a two-regime running model with a sprint segment up to 400m and a Riegel endurance segment beyond 400m,
    \item Monte Carlo noise around both eating and running parameters.
\end{itemize}

The TOML file controls all of the meaningful athlete behavior. Sprint strength is set by \texttt{sprint\_ref\_time}; endurance is set by \texttt{ref\_time} and \texttt{type}/$k$; eating strength is set by the eating and post-eating parameters.
